# 节点编辑工作流 v0.1 · ComfyUI 同款架构说明

> 本项目是对 ComfyUI v0.9.2（绘世启动器整合包）前端/后端的**逐行逆向复刻**，
> 逆向方法与证据见 [`docs/ComfyUI逆向分析报告.md`](./ComfyUI逆向分析报告.md)。
> 本文说明新系统的架构、运行方式与二次开发入口。

## 1. 一句话总览

用 **litegraph.js 0.7.18**（ComfyUI 引擎的上游）做画布内核，外围按 ComfyUI 的规范重建：

| ComfyUI 概念 | 本项目实现 | 位置 |
|---|---|---|
| `/object_info` 节点表 | 同格式 API，434 个基础节点全量照搬 + 原生节点 | `server/registry/` |
| V1 节点 schema（INPUT_TYPES/RETURN_TYPES） | `NodeDef` 同构，前端按 schema 动态编译节点类 | `server/registry/types.ts`、`src/engine/nodeFactory.ts` |
| 连接规则（通配符/多类型/单输入） | litegraph 引擎原生规则 + ComfyUI 交互参数 | `src/engine/litegraphSetup.ts` |
| `validate_prompt` | `PromptValidator`（required 缺失/类型交集/min-max/强转） | `server/execution/validate.ts` |
| `ExecutionList` 拓扑调度 | 同款分批 + 环检测（DependencyCycleError） | `server/execution/executionList.ts` |
| prompt API / 队列 / history | 同格式路由 + FIFO 队列 + WS 事件 | `server/apiPlugin.ts`、`server/execution/queue.ts` |
| 工作流 JSON | litegraph `graph.serialize()` 原生产出（nodes/links/widgets_values） | `src/engine/ComfyGraph.ts` |
| `custom_nodes/` 插件 | `plugins/` 目录扫描 + 动态 import + `NODE_CLASS_MAPPINGS` | `server/plugins.ts` |
| ComfyUI-Manager | 插件管理对话框（GitHub 安装/启停/卸载） | `src/components/dialogs/PluginManagerDialog.vue` |
| DOM 控件层 | 覆写 `drawNodeWidgets` + `ctx.getTransform()` 定位 | `src/engine/widgets.ts`、`ComfyGraph.patchCanvas` |
| 官方 Dark 调色板 | 全部色值复刻（端口按类型着色） | `src/engine/litegraphSetup.ts` `SLOT_COLORS` |

## 2. 运行

```bat
start.bat
```

- **必须用项目内置 Node**（`runtime/node`，v22 / ABI 127）。原因：`better-sqlite3` 原生模块按 Node 22 编译，系统 Node 24（ABI 137）会在数据库初始化时崩溃。start.bat 已优先使用内置运行时。
- 启动后访问 http://localhost:5173
- 端口被占用时脚本会提示并退出（预检 5173）

## 4. 双轨执行模型

```
prompt 提交
   │
   ▼
PromptValidator（required/类型/值域）
   │
   ▼
全部节点有原生实现？ ──否──▶ 委托执行器（comfy-executor 插件）
   │                              POST 真实 ComfyUI + WS 事件回传 + /view 代理
   │是
   ▼
ExecutionList 拓扑分批（输出节点优先，环检测）
   │
   ▼
逐个执行原生 impl → 输出缓存 → WS 广播（executing/executed/progress）
```

- **原生节点**（文本/数学/图像/LLM）：TypeScript 本地执行，零外部依赖。
- **扩散类节点**（MODEL/LATENT/CLIP/VAE/SAMPLER…）：自动委托给真实 ComfyUI（绘世启动器那个），进度与图像通过 WS/`/view?source=comfy` 回显。在「设置」里配置 ComfyUI 地址即可。

### 两个 litegraph 0.7.18 ↔ ComfyUI fork 适配点

1. **`serialize_widgets`**：npm 版基类默认 falsy（仅内置 const 节点手动开启），ComfyUI fork 在基类改为 `true`。已在 `configureLiteGraph()` 全局开启，否则保存工作流会丢失全部控件值。
2. **`onRemoved` 钩子名**：litegraph 标准钩子是 `onRemoved`（节点移除/`graph.clear()` 时调用），写错成 `onRemove` 会导致 DOM 控件永不清理（重开工作流出现重复控件）。

## 8. 修复记录（2026-10-17）：官方节点全部失效的根因

### 8.1 症状

节点库里点 `LoadImage` / `PreviewImage` 等官方节点，节点标题是 `undefined`、没有端口、没有控件，
"载入图像后看不懂图像"、"文本显示只有一行"都由此派生。而原生名（`LoadImageNative`）的节点却一切正常。

### 8.2 根因链

```
ComfyUI 的输入声明有两种形态：
  ['IMAGE']                       ← 无配置对象（PreviewImage.images / ImageCompression...）
  ['INT', { default: 1, ... }]    ← 有配置对象
        ↓
nodeFactory 里 `const [rawType, cfg] = spec`，遇到第一种时 cfg === undefined
        ↓
读取 cfg.forceInput → TypeError
        ↓
litegraph createNode 用 try/catch 包住 `new base_class()`，异常被吞掉后 return null
        ↓
LGraph.configure 发现 node 为 null → `new LGraphNode()` 兜底，打上 has_errors
        ↓
画面上就是一个没有标题、没有端口、没有控件的空节点（且不报错）
```

| 文件 | 改动 |
|---|---|

### 9.3 「忽略节点」语义（bypass）

```ts
node.mode = 4                    // 4 = BYPASS（2 = MUTE/静音）
isBypassNode(n) → n.mode === 4
```

- **样式**：`onDrawForeground` 画橙色虚线外框 + 右上角斜纹 + 「已忽略」角标。
- **控件**：`refreshWidgetStates()` 把该节点全部控件行加 `.is-linked`（置灰 + label 删除线）。
- **执行**：`toPrompt()` 遇到 bypass 节点时**不产出该节点**，而是顺着同类型输入递归 `resolve()` 上游（最大深度 32），把上游值直接喂给下游；若本节点该输入有控件值，则退化成字面量。这样"中间节点忽略后链继续跑"是原语义，不是简单跳过导致下游断链。

### 9.4 组件对齐（胶囊行，ComfyUI 1.x 同款）

一行组件 = **胶囊行** `[名称 …… 值 ◀ ▶]`，值直接写在胶囊里（`.lg-field` 无边框透明），
不再靠"定宽名称列 96px"硬凑对齐：

```css
.lg-row  { display:flex; align-items:center; gap:4px; height:22px; padding:0 5px 0 4px; border-radius:6px }
.lg-label{ flex:0 0 auto; max-width:46%; font-size:12px; line-height:14px; ellipsis }
.lg-value{ flex:1 1 auto; justify-content:flex-end }   /* 值右对齐，ComfyUI 同款 */
.lg-field{ flex:1 1 auto; width:100%; height:18px; border:0; background:transparent; text-align:right }
```

- 左右内边距固定 → **所有节点、所有组件行的名称左边缘、值右边缘、行高都天然一致**（实测 ImageScale：左 756 / 右 1171 / 行高 25）。
- `:has(textarea)`（多行文本）→ 上下排列；`:has(.lg-seed-ops)` → 三列（标签/输入/骰子）；`has-suffix`（74/7 这类后缀）预留 44px。
- 所有 `setDisabled` 从 `style.opacity` 改为 `row.classList.toggle('is-linked', d)`，与 bypass 态共用一套视觉。
- 字体显式给栈 `Inter, "Segoe UI", "Microsoft YaHei", …`：DOM 控件层是绝对定位浮层，`input/select` 不会从 body 继承，之前落到浏览器默认**衬线体**（数字/英文变 Times）。

### 9.4.1 组件行即端口（widgets_start_y）

ComfyUI 1.x 里"有组件的输入"**不单独占端口行**：

```ts
// 只有"纯端口"（无 widget 的输入）才占行
node.widgets_start_y = Math.max(4, pureInputs * NODE_SLOT_HEIGHT + 4)
```

- `NODE_SLOT_HEIGHT = 26`，与组件行 22 + 间距 4 **同一栅格**，所以端口行与组件行不会错位。
- 端口点透明、`slot.label = ''`：视觉上那条线就接在组件行左边缘（`getConnectionPos` 把端点挪到 `pos[0] + 8`，与 INSET 一致）。
- 高度自适应：`refitNodeHeight()` 中纯端口行与输出行**共享栅格**（`if (outRows > contentRows) total += (outRows - contentRows) * slotH`），非弹性控件可收缩 → 导入工作流不再底部大片空白。

### 9.4.2 输出列（按输出名实测，别再写死）

组件行 DOM 会盖住画在节点右缘的输出端口 → 有输出的节点右侧必须留一列。

**先记住 litegraph 的真实几何（这一段是像素级实测反推出来的，别凭直觉）**：

```
输出端口锚点  getConnectionPos(false,i) → 本地 x = nodeW + 1 - NODE_SLOT_HEIGHT/2   (slotH=26 → nodeW-12)
输出名绘制    textAlign='right' + fillText(name, 锚点 - 10)  → 文本右缘 = nodeW - 22   （不是 nodeW-10！）
组件行右缘    nodeW - INSET - OUT_COL                        (INSET=8)
→ 间隔 gap = OUT_COL - textW - (1 + slotH/2)
→ 要留 10px 间隔：OUT_COL = textW + 10 + 1 + slotH/2
```

踩坑记录：第一版按 `nodeW - 10` 推公式，算出"间隔 14px"，但读画布像素只有 **3px**，
看上去就是"压住半个 I"。像素采样（`probe-pixels.mjs`）才是有说服力的口径，公式算出来的都不算。

```ts
private outNeed(node) {                             // 文本宽 + 10 间隔 + 1 + 半个端口行高
  ctx.font = this.canvas.inner_text_font            // normal 12.5px Inter/Segoe UI，与绘制一致
  return Math.ceil(max(measureText(name))) + 10 + 1 + Math.round(slotH / 2)
}
private outColWidth(node) {                         // 组件区最少留 40px
  return Math.max(34, Math.min(this.outNeed(node), node.size[0] - 16 - 40))
}
minSizeOf(node) {                                   // 最小宽度容得下输出列 + 120px 组件区
  return [Math.max(220, this.outNeed(node) + 16 + 120), ...]
}
```

- 不写死的原因还在于 `refitNodeHeight` 会把节点压到最小宽度；`minSizeOf` 同步按 `outNeed` 抬高下限，缩到最窄也不会重新压字。
- 全量验证：`.tools/probe-outcol-all.mjs` —— 457 个节点里 356 个带「输出 + 组件」，逐个压到最小宽度检查，**压字 0 个**。
- 像素验证：`.tools/probe-pixels.mjs` —— 直接读 `ctx.getImageData` 找输出名最左亮点，实测间隔：
  LoadImage `IMAGE` 12px、CLIPTextEncode `CONDITIONING` 11px、KSampler `LATENT` 12px、PrimitiveInt `INT` 12px、
  ControlNetApplyAdvanced `positive` 16px。
- 输出列变大后图片/多行文本跟着变窄，这是正确行为（组件区与输出列共享节点宽度）。

### 9.4.3 反序列化后重绑 slot ↔ widget（onConfigure）

`LGraphNode.prototype.configure` 会用 `cloneObject(info.inputs)` **整体替换 `inputs` 数组**，把构造函数里绑好的
`slot.widget / label / color` 全丢掉 → 表现是"导入工作流后组件下面多出一排纯端口行、`widgets_start_y=76`、控件不置灰"。

解法是覆写 litegraph 提供的钩子（在 inputs 重建后、`widgets_values` 写回后调用）：

```ts
onConfigure(info: unknown) {
  // ① 按「控件名 == 输入名」重建 slot.widget / label='' / color_on|off='transparent'
  // ② 按 valueSlots 游标重放 widgets_values
  // ③ colorizePorts() + syncDom() + refreshWidgetStates()
}
```

配套 `onSerialize(o)` 反向写出：**一个控件可能占多个 `widgets_values` 槽**（`valueSlots`），
例如 ComfyUI 的 `seed` 占 2 槽（种子 + 生成后控制），我们做成 1 个控件但序列化仍写 2 槽，
否则读真实工作流时后面所有参数整体错位一位。

### 9.5 图片控件弹性拉伸

`DOMWidgetOptions` 新增 `flexible / minHeight`：

- `computeSize()` 返回 `[w, minHeight]` 占位；`drawNodeWidgets` 里 `flexH = nodeH - y - 6` → 图片吃掉节点剩余全部高度；
- `fullBleed`：`x = 0`、宽 = `nodeW`，贴满节点宽度；
- CSS：无黑底、`object-fit: contain`、`background: transparent`；
- **拉大无上限、缩小有下限**：`refitNodeHeight()` 用 `w.computeSize()` 计算最小高度（不能用 `offsetHeight`，弹性控件会自我放大）。

实测：节点 239 → 538 高，图片跟着 538；宽度 = 组件行宽（节点宽 − 内缩 16 − 输出列 30），右缘距节点右缘 38 图素。

### 9.6 缩放手柄

litegraph 原生命中区只有右下角 10×10 且要精确压在最后 5px。本轮自实现：

- `setupResizeHandle()` 在容器上 capture `pointerdown`，**距右下角 26px 内**（可略微超出节点边界）即进入缩放，`stopPropagation` 掉原生逻辑；
- `onResizeMove/onResizeUp` 自行 setSize，`minSizeOf()` 给下限，**向右/向下无上限**；
- 视觉：右下角常驻 3 道斜纹（alpha 0.34），悬停时铺半透明蓝色三角 + 加亮到 `#bcd8ff`。

### 9.7 组件隐藏输入端口（ComfyUI 同款）

端口现在是组件行 DOM 里的一个 `.lg-port`（不再是 canvas 上画出来的点），所以"浮现/按住/拖出"全靠 DOM 事件：

```css
.lg-port { opacity:0; pointer-events:auto }                    /* 必须可命中，否则 hover 打不亮、按不住 */
.lg-row:hover > .lg-port { opacity:1; transform:scale(1) }
.lg-row[data-linked='1'] > .lg-port { opacity:1; background:var(--port-color) }  /* 已连线常显实心点 */
```

`setupPortDrag()` 在容器上监听 **`mousedown`**（**不是 `pointerdown`**）：

1. 命中 `.lg-port` → 合成一个 `MouseEvent('mousedown')` 打到 canvas，让 litegraph 自己进入拖线态；
   合成事件 `which` 恒为 0，而 `processMouseDown/MouseUp` 用 `e.which == 1` 判左键，所以必须
   `Object.defineProperty(ev,'which',{value:1})`。
2. **不能在 `pointerdown` 里 `preventDefault()`**：那样后续兼容 mousemove 不再派发，`graph_mouse` 冻在起点（拖线拖到一半卡住）。用 `mousedown` + 只 `stopPropagation()` 即可。
3. litegraph 的 `connecting_input` 分支**不会设置 `connecting_slot`**，松手时执行 `node.connect(slot, connecting_node, undefined)` → 静默丢弃。
   在 `processMouseUp` 补丁里按目标节点上的输入下标回填：

```ts
if (connecting && inSlot && slot == null) {
  const idx = (connecting.inputs || []).indexOf(inSlot as never)
  if (idx >= 0) (this as any).connecting_slot = idx
}
```

4. 连线成功后 `refreshWidgetStates()` 把该控件行置灰失效，值来自上游（与 ComfyUI 完全一致）。

### 9.7.1 组（Group）

蓝色半透明框包住一群节点（`LGraphCanvas` 原生 `LGraphGroup` + 自绘 `drawGroups`）：

- **整组拖动**：按住组标题条拖动，组内节点一起位移（`mouse_drag_group`）。
- **统一忽略**：组菜单「忽略组内全部节点」→ 逐个 `mode = 4`，可再点一次恢复。
- **统一打标颜色**：组菜单 10 色板 → 组边框 + 标题条着色，组内节点标题条同步着色。
- **解散**：只删组，节点留着。

### 9.7.2 真多选

litegraph 原生多选在 `processMouseDown` 里"点到已选中节点就清空选区"，所以多选后一拖就散：

- 点中**已在选区内的节点** → 保持选区，进入整组拖动（`block_drag_node` 语义修正）。
- 右键命中选区内的节点 → **不清空选区**，菜单作用对象是整个选区（批量删除 / 批量忽略 / 批量编组）。
- `Ctrl+G` 把当前选区编成一个组。

const onlyNative  = ref(localStorage.getItem('comfy.onlyNative') !== '0')   // 默认 true

### 9.7.4 折叠节点时必须同步隐藏 DOM 组件层

litegraph 的 `drawNode` 在 `flags.collapsed` 时只画标题条（外加进出端口小点）然后 **直接 `return`**，
根本不会调用 `drawNodeWidgets` → 我们的 DOM 控件层收不到"隐藏"指令，会整块浮在折叠后的节点外面
（截图症状：折叠「数值显示」后，「执行后显示内容」的大块还挂在标题下面）。

修法是在 `drawNode` 上兜一层，每帧按折叠态切 DOM：

```ts
const origDrawNode = LGraphCanvas.prototype.drawNode
proto.drawNode = function (node, ctx) {
  const collapsed = !!node.flags?.collapsed
  for (const w of node.widgets || []) if (w.element) w.element.style.display = collapsed ? 'none' : ''
  return origDrawNode.call(this, node, ctx)
}
```

展开时 `drawNodeWidgets` 会重新写 `display=''` 并定位，两处互不冲突。
