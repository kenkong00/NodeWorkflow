# 草稿与发布节点分离存储方案

## 问题分析

### 当前数据架构

* **数据库表**: `custom_nodes` 表，所有节点（草稿和发布）存储在**同一张表**

* **状态区分**: 通过 `status` 字段（'draft' | 'published'）区分

* **发布机制**: `publish()` 方法直接将 `status` 从 'draft' 改为 'published'（同一行）

### 问题现象

1. 在草稿列表可以看到草稿
2. 发布后草稿从列表消失（因为 `status` 变成了 'published'）
3. 删除草稿会影响已发布的节点（因为是同一条数据）

### 用户需求

1. 草稿和发布节点**分开存储**
2. 删除草稿**不影响**已发布节点
3. 删除已发布节点**不影响**草稿

***

## 解决方案：复制发布模式

### 核心设计

**发布时复制（Copy-on-Publish）**:

* 草稿始终保存在 `node_drafts` 表

* 发布时**复制**草稿数据到 `node_published` 表

* 原草稿保持不变

* 两个表完全独立，互不影响

***

## 数据库 Schema 修改

### 1. 创建 `node_drafts` 表（从现有 `custom_nodes` 迁移）

```sql
CREATE TABLE IF NOT EXISTS node_drafts (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL UNIQUE,
  category TEXT NOT NULL DEFAULT '自定义',
  icon TEXT DEFAULT 'Box',
  description TEXT DEFAULT '',

  -- 结构定义 (JSON)
  controls TEXT NOT NULL DEFAULT '[]',
  inputs TEXT NOT NULL DEFAULT '[]',
  outputs TEXT NOT NULL DEFAULT '[]',

  -- 样式引用
  node_style_id TEXT,
  port_style_id TEXT,
  control_style_id TEXT,

  -- 元数据
  width INTEGER DEFAULT 240,
  height INTEGER DEFAULT 0,
  is_resizable INTEGER DEFAULT 1,

  -- 关联的已发布节点ID（如果有）
  published_node_id TEXT,

  -- 时间戳
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 2. 创建 `node_published` 表

```sql
CREATE TABLE IF NOT EXISTS node_published (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL UNIQUE,
  category TEXT NOT NULL DEFAULT '自定义',
  icon TEXT DEFAULT 'Box',
  description TEXT DEFAULT '',

  -- 结构定义 (JSON)
  controls TEXT NOT NULL DEFAULT '[]',
  inputs TEXT NOT NULL DEFAULT '[]',
  outputs TEXT NOT NULL DEFAULT '[]',

  -- 样式引用
  node_style_id TEXT,
  port_style_id TEXT,
  control_style_id TEXT,

  -- 元数据
  width INTEGER DEFAULT 240,
  height INTEGER DEFAULT 0,
  is_resizable INTEGER DEFAULT 1,

  -- 关联的源草稿ID
  source_draft_id TEXT,

  -- 版本号
  version INTEGER DEFAULT 1,

  -- 是否启用
  is_enabled INTEGER DEFAULT 1,

  -- 时间戳
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 3. 控件实例表修改

```sql
-- 控件实例现在关联到草稿
CREATE TABLE IF NOT EXISTS node_control_instances (
  id TEXT PRIMARY KEY,
  node_id TEXT NOT NULL,  -- 指向 node_drafts.id
  ...
);

-- 添加 published_node_id 字段引用已发布节点
ALTER TABLE node_published ADD COLUMN source_draft_id TEXT;
```

## 发布流程变更

### 新发布流程

1. 用户点击"发布节点"
2. 后端复制草稿数据到 `node_published` 表
3. 更新草稿的 `published_node_id` 字段指向新发布的节点
4. 返回已发布节点数据
5. 草稿列表中草稿仍然显示（带"已发布"标记）

### 新删除流程

* **删除草稿**: 只删除 `node_drafts` 中的记录和关联的控件实例

* **删除已发布节点**: 只删除 `node_published` 中的记录

* 两者互不影响

### 再发布流程（编辑后重新发布）

1. 用户编辑草稿内容
2. 用户点击"发布节点"
3. 后端检查该草稿是否已有 `published_node_id`

   * **如果有**: 更新对应的 `node_published` 记录（版本号 +1）

   * **如果没有**: 创建新的 `node_published` 记录
4. 草稿的 `published_node_id` 指向最新的已发布节点
5. 多次发布会产生多个版本记录，可追溯历史版本

### 草稿与已发布节点的关联

```
node_drafts                          node_published
+-----------+                        +------------------+
| id        |◄──── source_draft_id  | id               |
| name      |                        | name             |
| type      |                        | type             |
| published_node_id ─────────────────►| version          |
+-----------+                        +------------------+
```

## 现有功能兼容性说明

### ✅ 不受影响的功能

| 功能          | 实现方式                          | 说明                                |
| ----------- | ----------------------------- | --------------------------------- |
| **删除草稿**    | 调用 `DELETE /api/drafts/:id`   | 只删除 `node_drafts` 表中的记录，已发布节点不受影响 |
| **修改草稿**    | 调用 `PUT /api/drafts/:id`      | 只更新 `node_drafts` 表中的记录           |
| **重新发布**    | 发布时创建**新的**已发布记录              | 保留旧的已发布节点，可选择是否清理                 |
| **查看草稿列表**  | 调用 `GET /api/drafts`          | 始终从 `node_drafts` 表读取             |
| **查看已发布列表** | 调用 `GET /api/published-nodes` | 始终从 `node_published` 表读取          |

### 🔄 行为变化

| 场景       | 旧行为       | 新行为                   |
| -------- | --------- | --------------------- |
| 发布草稿后    | 草稿从列表消失   | 草稿保留在列表中，带"已发布"标记     |
| 删除已发布节点  | 可能影响草稿    | 只删除已发布节点，草稿完整保留       |
| 同一草稿多次发布 | 覆盖同一已发布记录 | 每次发布创建新的已发布节点记录（版本递增） |
