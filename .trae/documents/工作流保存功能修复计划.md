# 工作流保存功能修复计划

## 🐛 问题诊断

### 根本原因分析

经过代码审查，发现 **3 个连环问题** 导致工作流无法持久保存：

#### 问题1: Store 设计为单工作流模式
**文件**: [comfyui.ts:25](src/stores/comfyui.ts#L25)
```typescript
const workflow = ref<WorkflowAPI | null>(null)  // ❌ 只存一个！
```
- `saveWorkflow()` 每次调用都会**覆盖**之前的值
- `loadWorkflow()` 只加载**一个**工作流

#### 问题2: WorkflowEditor 的 workflows 纯内存存储
**文件**: [WorkflowEditor.vue:126](src/components/tools/WorkflowEditor.vue#L126)
```typescript
const workflows = ref<WorkflowAPI[]>([])  // ❌ 刷新即丢失！
```
- 这是一个纯内存数组，没有任何持久化机制
- 页面刷新 → 数据清空 → 重新从 store 加载（但 store 也只有一个）

#### 问题3: 删除操作不同步到存储
**文件**: [WorkflowEditor.vue:238-247](src/components/tools/WorkflowEditor.vue#L238-L247)
```typescript
const deleteWorkflow = async (id: string) => {
  workflows.value = workflows.value.filter(w => w.id !== id)  // ❌ 只删内存
  // 没有任何持久化操作！
}
```

### 数据流向图（当前错误流程）

```
用户点击"保存"
    ↓
handleSaveWorkflow()
    ↓
┌─────────────────┐     ┌──────────────┐
│ workflows 数组   │ ←── │ store.save   │  ← 后端 /api/workflow (只存1个)
│ (内存, 刷新丢失) │     │ Workflow()   │
└─────────────────┘     └──────────────┘
         ↑                      ↓
    loadWorkflows()        后端可能不持久
         ↓                      ↓
    [store.workflow]      重启/刷新 → 数据丢失
    (只有1个或null)
```

---

## ✅ 修复方案

### 核心策略: **localStorage 前端持久化**

不再依赖后端 API 存储多工作流列表，改用 **localStorage** 直接管理：
- ✅ 多个工作流独立存储
- ✅ 刷新页面数据保留
- ✅ 不依赖后端实现
- ✅ CRUD 操作实时同步

### 修改范围

只需修改 **1个文件**: [WorkflowEditor.vue](src/components/tools/WorkflowEditor.vue)

---

## 🔧 具体实施步骤

### 步骤1: 添加 localStorage 工具函数

在 `<script setup>` 中添加以下常量和函数：

```typescript
// ====== localStorage 持久化键名 ======
const WORKFLOWS_STORAGE_KEY = 'workflow_editor_workflows'

// ====== 持久化工具函数 ======

/** 将 workflows 数组保存到 localStorage */
function persistWorkflows(data: WorkflowAPI[]) {
  try {
    localStorage.setItem(WORKFLOWS_STORAGE_KEY, JSON.stringify(data))
  } catch (err) {
    console.error('保存工作流列表到本地存储失败:', err)
  }
}

/** 从 localStorage 加载 workflows 数组 */
function loadPersistedWorkflows(): WorkflowAPI[] {
  try {
    const raw = localStorage.getItem(WORKFLOWS_STORAGE_KEY)
    if (!raw) return []
    const parsed = JSON.parse(raw)
    if (Array.isArray(parsed)) {
      // 验证每个项的基本结构
      return parsed.filter((item: any) =>
        item && item.id && item.name && typeof item.content === 'object'
      ) as WorkflowAPI[]
    }
    return []
  } catch (err) {
    console.error('加载工作流列表失败:', err)
    return []
  }
}
```

### 步骤2: 修改 `loadWorkflows()` 函数

**当前代码（第142-147行）**:
```typescript
const loadWorkflows = async () => {
  await store.loadWorkflow()           // ❌ 从后端加载单个
  if (store.workflow) {
    workflows.value = [store.workflow] // ❌ 只有1个
  }
}
```

**修改为**:
```typescript
const loadWorkflows = () => {
  // 优先从 localStorage 加载多工作流列表
  const persisted = loadPersistedWorkflows()
  if (persisted.length > 0) {
    workflows.value = persisted
    console.log(`[WorkflowEditor] 从本地存储加载 ${persisted.length} 个工作流`)
  } else {
    // fallback: 尝试从 store 迁移旧数据
    workflows.value = []
    if (store.workflow) {
      workflows.value = [store.workflow]
      persistWorkflows(workflows.value) // 迁移到新存储
    }
  }
}
```

**关键变化**:
- 不再 `await store.loadWorkflow()`
- 直接从 localStorage 读取完整数组
- 自动迁移旧的单工作流数据

### 步骤3: 修改 `handleSaveWorkflow()` 函数

**当前代码（第249-279行）**:
```typescript
const handleSaveWorkflow = async () => {
  // ...验证逻辑...
  
  await store.saveWorkflow(workflowData)  // ❌ 调用后端(覆盖式)
  
  const existingIndex = workflows.value.findIndex(...)
  if (existingIndex >= 0) {
    workflows.value[existingIndex] = workflowData
  } else {
    workflows.value.push(workflowData)
  }
  // ❌ 缺少 persistWorkflows() 调用！
}
```

**修改为**:
```typescript
const handleSaveWorkflow = async () => {
  if (!isValid.value) {
    showSaveMessage('请先修正 JSON 格式', true)
    return
  }

  try {
    const content = JSON.parse(jsonContent.value)

    const workflowData: WorkflowAPI = {
      id: selectedWorkflow.value?.id || `workflow-${Date.now()}`,
      name: editingName.value || '未命名工作流',
      content,
      createdAt: selectedWorkflow.value?.createdAt || Date.now(),
      updatedAt: Date.now()
    }

    // 更新本地数组
    const existingIndex = workflows.value.findIndex(w => w.id === workflowData.id)
    if (existingIndex >= 0) {
      workflows.value[existingIndex] = workflowData
    } else {
      workflows.value.push(workflowData)
    }

    selectedWorkflow.value = workflowData
    isNewWorkflow.value = false

    // ✅ 关键: 立即持久化到 localStorage
    persistWorkflows(workflows.value)

    showSaveMessage(`工作流已保存 (${workflows.value.length}个总计)`, false)
  } catch (err) {
    showSaveMessage(`保存失败: ${err instanceof Error ? err.message : err}`, true)
  }
}
```

**关键变化**:
- 移除 `await store.saveWorkflow(workflowData)` 调用
- 在数组更新后立即调用 `persistWorkflows()`
- 保存消息显示总数，让用户知道有多少个工作流

### 步骤4: 修改 `deleteWorkflow()` 函数

**当前代码（第238-247行）**:
```typescript
const deleteWorkflow = async (id: string) => {
  if (confirm('确定要删除这个工作流吗？')) {
    workflows.value = workflows.value.filter(w => w.id !== id)
    // ...清理选中状态...
    showDeleteMessage('工作流已删除')
    // ❌ 缺少 persistWorkflows() 调用！
  }
}
```

**修改为**:
```typescript
const deleteWorkflow = (id: string) => {
  if (confirm('确定要删除这个工作流吗？')) {
    workflows.value = workflows.value.filter(w => w.id !== id)
    
    if (selectedWorkflow.value?.id === id) {
      selectedWorkflow.value = null
      jsonContent.value = ''
    }
    
    // ✅ 关键: 立即同步到 localStorage
    persistWorkflows(workflows.value)
    
    showDeleteMessage(`工作流已删除 (剩余${workflows.value.length}个)`)
  }
}
```

**关键变化**:
- 移除 `async`（不再需要等待）
- 删除后立即调用 `persistWorkflows()`
- 消息显示剩余数量

## ⚠️ 注意事项

1. **向后兼容**: 如果用户之前通过后端保存了工作流，首次加载时会自动迁移到 localStorage
2. **数据安全**: localStorage 是明文存储，不适合敏感数据（但工作流JSON通常不敏感）
3. **容量限制**: 浏览器 localStorage 通常 5MB 限制，对于文本型工作流足够用
4. **跨标签页**: 如果同时打开多个标签页编辑，最后一个保存的操作会生效（正常行为）
